# Chat Route

`app/api/chat/route.js` handles all conversational AI surfaces in the app: the Lens chat (`/myai`), visitor AI on public profiles (`/{handle}/ask`), and onboarding flows.

---

## Modes

The route detects three operational modes per request:

- **Onboarding:** `< 3 recs OR no bio`. Loads onboarding skill stack. Inviter context + welcome framing.
- **Standard:** `3+ recs AND bio`. Loads standard skill stack. Full taste profile + network context.
- **Visitor:** another curator's `/ask` page. Visitor prompt is currently inlined (not yet extracted to skill system).

Mode detection happens early in the request handler. Subsequent prompt construction branches on mode.

---

## Pre-builders

Two transformations applied to every system prompt regardless of mode:

1. **Today's date prepended.** Date hallucination defense. Without this, the model occasionally references stale dates from training data.
2. **`tasteProfileBlock` wrapped in markers.** When the user has a generated `taste_profiles.content`, it's wrapped as:

```
=== CURATOR REFERENCE DOCUMENT ===
<full taste profile markdown>
=== END REFERENCE DOCUMENT ===
```

The wrapper instructs the AI to use the document as factual reference but NOT to mirror its voice in responses. This was added to prevent the chat route from echoing the Record's interpretation framing back at the user.

---

## Network context

`getSubscribedRecs(profileId)` from `lib/chat/network-context.js` injects recent recommendations from curators the user subscribes to. Each rec line carries a `[REC_LINK: /<handle>/<slug>]` sentinel. The system prompt instructs the AI to render these sentinels as markdown links in responses.

Network context is gated on `!tasteReadUrl` — suppressed on Read turns to avoid adding noise to the chip-generation context. (Note: chip generation actually happens in `/api/taste-read/route.js`, not here. The chat route's Read short-circuit just emits a card; see Read short-circuit section below.)

---

## Link handling

Synchronous. Up to 3 URLs parsed concurrently with a 15-second timeout per URL.

Parsed content persists to `chat_messages.parsed_content` on the AI's response message. Re-injection within a 5-message window via `distillForReinjection` from `lib/chat/link-parsing.js`. Each re-injected block capped at ~800 chars; max 2 blocks total injected per turn.

The re-injection path checks `rec_refs` first (rec saved from this URL → fetch from `rec_files` → inject via `buildRecFileContextBlock`). No fallback to raw `parsed_content` — that path was removed April 13, 2026 to prevent stale parser output from polluting context.

---

## Hard cap

`SYSTEM_PROMPT_HARD_CAP = 180_000` characters. `enforceSystemPromptCap()` applied before all 3 `anthropic.messages.create` call sites (opening, main, tool_loop).

Per-path additive caps:

- 40K for `linkContextBlock`
- 40K for `rec_files` re-injection
- 40K for taste-read re-injection

## Action buttons emitted

The chat route emits structured `action_buttons` blocks alongside text. Client renders these as tappable buttons. Action strings the route emits:

- `save_rec_from_chat:<url>` — opens QCS prefilled with URL
- `taste_read:<url>` — triggers Read short-circuit (button label is "Add to Record")
- `discuss_link:<url>` — silent meta-action, no UI button visible
- `save_image_rec:<sha256>` — Feature B, opens QCS in upload mode
- `save_rec_from_taste_read:<url>` — opens QCS with URL + metadata prefilled, Why blank

### Three-option URL-drop block

Emits unconditionally on URL drops. Three buttons in this order: Save as Recommendation / Add to Record / Just talk about it.

Suppressed only when:
- No `parsedLinkBlock` entry (parsing failed)
- A `[REC]` block was emitted same turn (rec capture happened)
- The message is a follow-on from one of these buttons (avoid re-emitting on each turn of the resulting flow)

---

## Read short-circuit

When a chat turn contains a "Do a Read on <url>" trigger (typically generated by clicking the Add to Record button), the route short-circuits at line 247.

Behavior:
- Does NOT call Claude on the chat side.
- Emits a `taste_read_card` block carrying `parsed_content` + `source_url`.
- Returns immediately.

The actual chip generation runs separately in `/api/taste-read/route.js` after the client mounts `TasteReadCard`. See `docs/read-pipeline.md` for the full Read flow.

---

## Rec capture

The AI emits `[REC]{...}[/REC]` JSON when it detects a savable recommendation in the user's message. Server-side validation:

- `validateRecContext` walks history backwards from the current turn
- Skips pure affirmations ("yes", "ok", "nice")
- Picks the first substantive message as the rec context
- Validates required fields, normalizes values
- Persists via the standard rec save path

This server-side validation is the load-bearing guard against AI hallucinated `[REC]` blocks. Prompt-level rules alone are not sufficient — the model occasionally emits `[REC]` for messages that don't actually contain a rec.

---

## Tool use

`get_curator_stats` is the only registered tool. Definition + handler: `lib/chat/stats-tool.js`. Registered only when `!isVisitor && !isOnboarding && !!profileId` — a one-hop loop per request.

**Critical text extraction pattern:** Use `response.content.find(b => b.type === 'text')?.text`. Do NOT revert to `content[0].text` — on tool-use turns, the first content block is `tool_use`, and indexing position 0 silently drops the AI's reply.

---

## Post-save reflection

Post-save user-message injection lives in `ChatView.jsx`, not in this route:

- Line 227: `handleQuickCaptureSaved` (QCS save path)
- Line 850: `handleSaveCapture` (inline save path)

Both fire `[SYSTEM: ...]`-prefixed user messages with charter-aligned constraints inline (max 2 sentences, exactly one question mark, no verdicts). Universal — applies to both stable and staging AI lanes.

**If post-save behavior drifts, debug `ChatView.jsx` FIRST.** Do not start with skill files. The post-save constraint enforcement is in the injection text, not the skill.

## Charter

The Lens Charter (`lib/prompts/skills/staging/charter.md`) loads FIRST in staging prompt builders via conditional spread. Defines:

- AI role
- Three turn branches: capture, discover, talk-through
- Five banned behaviors
- Direct-ask exception (when the user explicitly asks Lens to characterize their taste, give a real answer, not a deflection)

The stable `lib/prompts/charter.md` is a placeholder, never read. Charter only applies to staging users.

## Known issues

- **CHAT-VERBOSITY (P1):** URL-paste responses inject the full taste profile + 15 recent recs and produce context-aware comparative essays. When the user pastes URLs in succession (e.g., to do Reads on each), the chat route's intermediate responses synthesize across articles even when the user just wants the action buttons. Options to fix: gate `tasteProfileBlock` and `recsContext` on URL-drop turns; introduce a "minimal mode" prompt branch; tighten the prompt to suppress comparative synthesis. Recommendation favors structural gating over soft caveats — soft caveats failed in READ-DRIFT.
